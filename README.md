# 무채색에서 살아남기 — Frontend

부스용 얼굴 사진 촬영, 퍼스널컬러 결과 조회, 롬앤 제품 추천, 가상 메이크업 Before/After 및 QR 결과 카드를 제공하는 HTML/CSS/JavaScript 프론트엔드입니다.

## 포함 기능

- 브라우저 카메라 촬영, 3초 카운트다운 및 재촬영
- 촬영·분석 동의 확인과 가상 메이크업의 별도 처리 동의
- 퍼스널컬러 유형, 추천 팔레트, 옷·머리색·액세서리 스타일 표시
- v2 분석 근거, 촬영 조건 안내, 경고 문구 및 유형별 참고 점수 표시
- 백엔드 제품 API를 이용한 롬앤 제품·현장 테스터 안내
- 메이크업 색상·강도 선택과 Before/After 비교 슬라이더
- 만료형 공유 링크를 이용한 QR 발급 및 얼굴 사진 없는 공개 결과 카드
- 다음 참가자 초기화와 사진·결과 즉시 삭제 요청
- 카메라·백엔드 없이 확인하는 데모 미리보기
- 테스트용 API 응답과 가상 카메라를 이용한 브라우저 검증

> 분석 결과는 조명·카메라·촬영 각도에 영향을 받는 체험용 추천입니다. 전문 퍼스널컬러 진단이나 피부/의료 진단을 대체하지 않습니다.

## 빠른 실행

Python 3와 Chrome이 필요합니다. 별도 프론트 빌드 과정은 없습니다.

백엔드 담당자가 제공한 최신 `ai-verse-be` 서버를 8000번 포트에서 정상 실행한 뒤, 이 프론트 폴더에서 실행합니다.

```powershell
python -m http.server 5173 --bind 127.0.0.1
```

Chrome에서 <http://localhost:5173/1.html>을 엽니다. 로컬 5173·3000번 포트에서는 API를 `http://localhost:8000`으로 요청합니다. BE의 CORS 허용 주소에 `http://localhost:5173`이 포함돼야 합니다.

실제 사진 테스트는 프론트 서버와 BE가 모두 실행 중이어야 합니다. HTML 파일을 직접 여는 방식은 데모 미리보기만 지원합니다. YouCam 키와 공급자 설정은 BE에서 관리하며 프론트에 넣지 않습니다.

## 체험 흐름

1. 부스 소개 및 촬영·개인정보 처리 동의 확인
2. 포토박스에서 얼굴 촬영 및 사진 확인
3. 백엔드로 사진을 전송해 퍼스널컬러 분석 요청
4. 계절 유형, 추천 팔레트, 분석 근거 및 스타일 확인
5. 원하는 참가자의 메이크업 색상·강도 선택 및 별도 동의
6. 가상 메이크업 적용 후 Before/After 비교
7. 운영자 안내에 따라 실제 제품 손등 발색 또는 진단천 체험
8. QR로 휴대폰에서 결과 카드 확인
9. 다음 참가자를 위한 초기화 또는 사진·결과 삭제 요청

## 백엔드 연동

- 상태 확인: `GET /health`
- 사진·동의 전송: `POST /api/v1/analyses`
- 분석 결과 조회: `GET /api/v1/analyses/{analysis_id}`
- 제품 추천: `GET /api/v1/analyses/{analysis_id}/products`
- 가상 메이크업: `POST /api/v1/try-ons`
- 공유 링크 발급: `POST /api/v1/analyses/{analysis_id}/share`
- 공개 결과 조회: `GET /api/v1/public/results/{token}`
- 사진·결과 삭제: `DELETE /api/v1/analyses/{analysis_id}`

가상 메이크업 응답의 `before_image_url`과 `result_image_url`을 비교 화면에 표시합니다. 분석 ID와 보관 만료 시각은 브라우저 세션에 저장합니다. 프론트 연결 코드는 구현되어 있으며, 실제 BE·YouCam 통합 테스트는 별도로 진행해야 합니다.

## 최신 분석 결과 표시

- 기존 `season`, `season_ko`, `palette`, `recommendations` 응답을 지원합니다.
- v2의 `content`를 이용해 요약, 키워드, 이름 있는 팔레트, 옷·머리색·액세서리, 메이크업과 부스 추천 립을 표시합니다.
- `season_scores`는 유형별 참고 점수로 표시합니다. 진단 정확도나 확률로 표현하지 않습니다.
- `reasons`, `reliability`, `warning_messages`를 결과 화면과 공개 카드에서 표시합니다. BE 공개 응답에 없는 유형별 전체 점수는 임의로 만들지 않습니다.
- v2 필드가 없는 legacy 응답도 지원합니다.

## 동의와 보관 안내

운영자는 촬영 전에 서면 동의와 개인정보 처리 안내를 진행합니다. 참가자는 2페이지에서 촬영·분석 동의를 확인해야 카메라를 열거나 사진을 전송할 수 있습니다. 분석 요청 전 동의를 해제하면 이 화면의 카메라를 중지하고 촬영 미리보기를 폐기합니다.

가상 메이크업은 결과 화면에서 별도로 동의를 확인합니다. 외부 서비스 사용 시 사진이 YouCam으로 전송될 수 있음을 안내합니다. 외부 서비스의 보관·삭제 조건은 운영자가 별도로 확인해 안내해야 합니다.

서버 보관 기본값은 24시간이며 실제 설정은 BE가 관리합니다. 결과 응답의 `expires_at`을 기준으로 보관 만료 예정 시각을 보여줍니다. 만료 데이터의 실제 정리는 BE의 정리 주기를 따릅니다.

## 체험 종료와 즉시 삭제

결과 페이지와 QR 페이지에 두 가지 종료 방법이 있습니다.

- **QR 유지하고 다음 참가자**: 현재 브라우저의 분석 ID·만료 시각만 초기화합니다. `DELETE`를 호출하지 않아 기존 QR은 서버의 만료·삭제 기준까지 유지됩니다.
- **사진·결과 삭제하고 종료**: 확인창을 거쳐 `DELETE /api/v1/analyses/{analysis_id}`를 요청합니다. BE의 `204` 성공 또는 이미 없어진 결과의 `404`를 받으면 브라우저 세션을 초기화합니다. 네트워크·서버 오류에서는 결과를 유지하고 재시도할 수 있습니다.

현재 BE는 분석 삭제 시 원본 사진·가상 메이크업 결과와 공유 링크도 함께 삭제합니다. 따라서 가이드의 '체험 종료 시 삭제'를 모든 초기화에 자동 적용하면 QR 수령 기능을 유지할 수 없습니다. 현재 FE는 두 선택지를 분리했으며, 행사 운영 시 사용할 기본 정책은 팀과 맞춰야 합니다. 이미 내려받은 파일이나 외부 서비스 보관 데이터에는 이 삭제 요청이 적용되지 않습니다.

## 화면 미리보기

2페이지의 임시 이동 버튼은 `3.html?demo=1`, `4.html?demo=1`을 엽니다. 예시 결과와 메이크업 일러스트를 사용하고 실제 분석·외부 전송·삭제 요청은 하지 않습니다. 2페이지의 `data-test-mode` 속성을 제거하면 임시 버튼이 숨겨집니다.

## 휴대폰 QR

배포 시 휴대폰과 부스 컴퓨터에서 함께 접속할 수 있는 HTTPS 주소를 사용하고, 같은 주소의 `/api/`와 `/health`를 BE로 전달해야 합니다. `localhost` QR은 다른 기기에서 열 수 없습니다.

FE는 공유 토큰으로 `4.html#result=...` 결과 카드 주소를 만들며, 공개 카드에는 얼굴 사진을 표시하지 않습니다. 공유 링크와 분석의 만료 시각 중 빠른 시각을 QR 화면에 표시합니다.

## 테스트

Node.js, Playwright와 Chrome이 있는 환경에서 실행합니다.

```powershell
node tests/frontend.cjs
```

Playwright가 별도 위치에 설치되어 있으면 `AI_VERSE_PLAYWRIGHT`에 모듈 경로를 지정할 수 있고, `AI_VERSE_BROWSER`로 브라우저 실행 파일을 지정할 수 있습니다.

검증은 가상 카메라와 테스트용 API 응답으로 동의 차단, 업로드, v2·legacy 결과, 메이크업, QR 유지, 삭제 성공·실패·재시도, 공개 카드, 반응형 화면을 확인합니다. 실제 BE·YouCam 통합 테스트나 분석 정확도 검증을 대신하지 않습니다. 결과와 스크린샷은 Git에서 제외되는 `.preview/`에 생성됩니다.
